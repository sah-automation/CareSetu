# Brief - T01 Care Schema Migration & DTO Models

**Ticket:** #417 · **Parent:** #416 · **Refreshed:** 2026-09-14
**Reading surface:** ~6K tokens (budget 10K) - within budget

## Scope

Create migration `v8_0__init_care` that creates all `care`-prefixed tables in the `care` schema: `care_cases` (patient_id, doctor_id, pre_summary_id, stage enum, closed_at, close_reason), `care_prescriptions` (case_id, status enum, source enum ai_draft/manual, attempt_no, draft_snapshot jsonb, issued_at, attributed_doctor), `care_rx_items` (prescription_id, sequence, name, dose, duration), `care_rx_approvals` (prescription_id, doctor_id, decision, edited_yn, reason, verification_declaration, declared_at, approved_at), `care_doctor_inputs` (case_id, input_type enum voice/photo, media_ref, sensitive_class), plus `care_outbox` and `consumed_events` using the shared outbox DDL. No cross-schema FKs; cross-identity columns are plain BigInteger per ADR-0003.

Also create `care_models.py` as the DTO leaf module with typed Pydantic result views and the `CARE_SCHEMA` constant.

## Handoff notes

- The `care` schema already exists (created by `v0_0__bootstrap_schemas`). The migration adds tables to it - does NOT create the schema.
- Use `op.execute()` with raw SQL strings (the repo convention for all migrations).
- Enum types should be created as PostgreSQL ENUMs in the `care` schema (e.g., `care.case_stage`, `care.rx_status`).
- The `care_outbox` table shape must match `bus.outbox_ddl.outbox_table` output exactly.
- Cross-identity columns (patient_id, doctor_id) are plain `BigInteger` with NO FK constraint (ADR-0003 module isolation).
