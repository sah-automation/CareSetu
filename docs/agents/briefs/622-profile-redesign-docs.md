- **ADR-0022 must name the rejected alternatives, not just the choice.** The four are interactive map pin selection, a geocoding service, address autocomplete, and browser geolocation. - **Glossary entries: match the existing shape or they will read as drift.** Every canonical term in `CONTEXT.md` is a bolded term, a definition, and an `_Avoid_` list. Five changes are in scope: add **locality** (the neighbourhood a practice sits in; avoid "area", "sector", "colony"), add **clinic name** (the optional clinic or hospital, distinct from the doctor's own name; avoid treating it as the display name), revise **specialty** (a doctor holds one or more values from a closed list, and the list is no longer null; the entry keeps "never free-form" and drops the single-value implication; "consultation type" and "expertise" stay on the avoid list), revise **directory entry** (its geo point is the derived practice position, written whenever the declared address is saved, rather than frozen at activation), and demote **service area** (the table, the seeded Daltonganj row and the column stay because registration still resolves them, but no user-visible surface renders the name any more; search has always used the 25 km peri-urban radius as its real constraint). Then add the explicit verified-versus-declared statement: credentials are verified, profile detail is declared, and verified gains no coverage of the declared fields. That statement needs a name because the page now makes the distinction visually.
- **The service-area demotion is a documentation change, not a deletion.** Say so in the glossary. Registration still resolves the vocabulary and the column stays; removing them is separate cleanup and is explicitly out of scope.
